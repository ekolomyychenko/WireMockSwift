# Тестирование WireMockSwift

Как мы тестим библиотеку и покрываем автотестами новый функционал. Документ —
рабочий свод правил и чек-листов; пользовательская дока в `README.md`, устройство
кода — в `ARCHITECTURE.md`.

Две сквозные цели, которым подчинено всё ниже:

- **Zero-bug policy** — баги ловим до релиза, а не после. «Отложено» допустимо
  только осознанно и зафиксированно (см. известные гэпы), а не по недосмотру.
- **Паритет с Java WireMock (закреплённая версия — 3.13.2)** в приоритете. Тесты
  должны доказывать, что Swift-DSL и Admin-клиент ведут себя так, чтобы человек с
  Java-WireMock мог опираться на официальную доку.

## Принципы

1. **Позитив и негатив вместе.** Любой матчер/проверка тестируется и на попадании
   (должно совпасть → 200), и на промахе (не должно → 404). Сломанный матчер,
   который «всегда матчит», обязан ронять тест. Для ассертов — есть и `should`, и
   `should not`.
2. **Никаких «2+2».** Проверка «1 метод из 100 — значит всё ок» не принимается.
   Покрытие меряется не числом тестов, а тем, какие ветки и контракты реально
   зафиксированы.
3. **Детерминизм.** Никакой зависимости от времени, порядка ключей, случайности
   или сети без изоляции. Рандом — только через фиксированный seed, который
   печатается в сообщении об ошибке, чтобы падение воспроизводилось.
4. **Skip не маскируется под green.** Если интеграционному тесту нужен сервер,
   которого нет, локально он `XCTSkip`, но в CI (`WIREMOCK_REQUIRED=1`) — падает.
   Skip-шторм никогда не должен выглядеть как зелёный прогон.
5. **Падение указывает на место.** Хелперы пробрасывают `file`/`line` до места
   вызова, чтобы ошибка вела к тесту, а не в `TestSupport`.

## Слои тестов

Каждый слой закрывает свой класс рисков. Новый функционал, как правило, требует
нескольких слоёв, а не одного.

| Слой | Где | Что проверяет | Сервер |
|------|-----|---------------|--------|
| **Pure-unit** | `*PureTests`, `ClientUnitTests`, `ModelDecodingTests`, `JSONValueTests` | Детерминированные кирпичики: парсеры, матчеры, счётчики, рендер ошибок, декод/энкод | Нет |
| **Golden-encoding** | `GoldenEncodingTests` | DSL сериализуется ровно в ту JSON-форму, которую ждёт сервер. Сравнение **семантическое** (через `JSONValue`), порядок ключей не важен | Нет |
| **Property** | `PropertyTests` | Инварианты кодека на генеренных данных. Свой детерминированный PRNG (`SplitMix64`), фиксированный seed, воспроизводимо | Нет |
| **Live-integration** | наследники `WireMockIntegrationCase` (`*IntegrationTests`) | Реальное поведение против живого WireMock | Да |
| **Contract** | `ContractIntegrationTests`, `RecordedContractTests` | Паритет с Java 3.13.2: сервер принимает наши запросы (201, не 422), формы совпадают | Да |
| **Boundary / Error / Malformed** | `BoundaryTests`, `ErrorPathTests`, `MalformedInputTests` | Границы, кривой ввод, пути ошибок, экранирование | Смешанно |
| **Mocked transport** | `MockAdminTransport`, `RequestExpectationMockedTests` | Логика клиента без сети (детерминированный транспорт) | Нет |
| **Mutation** | `muter` (`.muter.conf.yml`, `Scripts/mutation.sh`) | Что golden/property-ассерты не «пустые»: мутируем исходник — тесты обязаны упасть. Скоуп — энкодеры | Нет |
| **XCUITest matrix** | `Examples/WireMockXCUIDemo` | Что клиент реально работает с iOS-симулятора против хостового сервера, на матрице мажорных версий iOS | Да |

## Чек-лист: покрываем новый функционал

Для новой фичи пройтись по списку и сознательно решить по каждому пункту (нужно /
не применимо):

- [ ] **Pure-unit** на все детерминированные кирпичики фичи (парсинг, счёт,
      формирование запроса/ошибки) — без сервера, быстро и воспроизводимо.
- [ ] **Golden-encoding**, если фича что-то сериализует в JSON для сервера —
      зафиксировать точную форму (семантически).
- [ ] **Live-integration** — минимум один тест на **попадание** и один на
      **промах**; для ассертов — и `should`, и `should not`.
- [ ] **Fail-path** — отдельно проверить текст/поведение ошибки (что диагностика
      понятная, а не «просто упало»).
- [ ] **Contract** — матчер/поле реально принимается WireMock 3.13.2 (201, не
      422). Если фича 4.x-only — покрываем только golden и явно это помечаем.
- [ ] **Boundary / malformed** — пустые значения, спецсимволы, экранирование,
      Unicode, большие числа, кривой ввод.
- [ ] **API-baseline** — если меняется публичная поверхность, обновить
      `api/WireMock.api.json` осознанно (`Scripts/api-check.sh --update`).
- [ ] **Mutation** — если трогали энкодеры, прогнать `Scripts/mutation.sh` и
      добить выживших мутантов (выживший мутант = пустой ассерт).
- [ ] **Покрытие не проседает** — гейт в CI ≥ 90% по `Sources` (реально ~97%).
      Цель не «100%», а отсутствие регрессии.

## Конвенции написания тестов

- **Doc-comment на файле-сьюте** объясняет, *зачем* он и что именно пинует — как в
  существующих сьютах. Не «что делает тест», а какой риск он закрывает.
- **Матчеры — match И miss** в одном сьюте (200 и 404), иначе матчер может «всегда
  матчить» и пройти.
- **Тайминги — только нижняя граница** (`assertTakesAtLeast`): нагрузка может
  только замедлить, поэтому такой ассерт не флакает вверх.
- **Серийно, не параллельно.** Интеграционные сьюты делят один сервер и сбрасывают
  его в `setUp`; `swift test` гоняем без `--parallel`.
- **Чистый baseline на входе.** `resetAll()` не чистит глобальную задержку и
  идущую запись — база `WireMockIntegrationCase` добивает это в `setUp`/`tearDown`;
  не полагаться на уборку предыдущего сьюта.
- **Только матчеры, принятые 3.13.2.** 4.x-only (напр. числовые матчеры) — покрываем
  golden-энкодингом и помечаем как non-server.
- **Без авто-ретраев в CI.** Настоящий флак должен оставаться видимым и
  переразгоняться руками, а не прятаться за retry.
- **Литерал в тесте — это тест-баг, если он не парсится.** Для compile-time JSON
  допустимо `trap`-ать (force-decode) вместо протаскивания `throws`.

## Как гоняем

- **Локально:** `Scripts/test.sh`. Живой сервер поднимается
  `Scripts/start-wiremock.sh` (пин версии + гейт готовности внутри).
- **CI** (`.github/workflows/ci.yml`): `swift test --enable-code-coverage` с
  `WIREMOCK_REQUIRED=1` (нет сервера → падаем, а не скипаем). Отдельный
  auth-инстанс на :8090 для `AdminAuthIntegrationTests`. Плюс джобы: SwiftLint
  `--strict`, API-стабильность + компиляция сниппетов, iOS-билд, XCUITest на
  матрице iOS 16→latest (+ iPad).
- **Покрытие:** мягкий гейт `MIN_COVERAGE=90` по `Sources`. Планку поднимаем вслед
  за фактом, никогда не выше реального числа.
- **Мутационное:** `Scripts/mutation.sh` — по требованию (медленно), не на каждый
  PR. Помни слепое пятно: muter гоняет без живого сервера, поэтому серверные пути
  (`expect(...)`: `refine`/`makeError`/`to*`) ему невидимы — их держат live-сьюты в CI.

## Definition of Done для PR с новым функционалом

PR считается готовым, когда:

1. Пройден чек-лист покрытия выше (по каждому пункту — решение принято).
2. Есть и позитивные, и негативные проверки.
3. Паритет с Java 3.13.2 подтверждён (contract-слой), расхождения — только
   осознанно отложенные и зафиксированные.
4. Зелёный CI целиком: тесты, покрытие ≥ порога, SwiftLint `--strict`,
   API-стабильность, iOS-билд и XCUITest-матрица.
5. Нет мусора от рефакторингов, комментарии и дока актуальны.
